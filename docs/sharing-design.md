# 用户隔离与标签层次分享设计

## 身份边界

`users.role` 只有 `superadmin` 和 `user` 两类。首次初始化只创建超级管理员，用户管理接口只能操作 `role=user`。HTTP 中间件在进入业务路由前校验身份与角色：超级管理员仅可使用会话、退出和 `/admin/users` 接口；普通账号可访问收藏业务，但不能访问管理接口。MCP 必须使用普通账号的 Bearer 密钥。

收藏和标签分别具有 `(user_id,digest)` 与 `(user_id,path)` 唯一索引。业务处理器取得当前用户的数据库上下文，GORM 的查询、更新、删除回调自动附加归属条件，创建回调填写归属；上下文贯穿事务和 MCP。模型设置使用 `user:<id>:<key>` 键空间。会话绑定用户，认证时始终检查账号仍存在且未停用。管理员操作使用内部无用户上下文连接，仅管理路由可达。

密钥采用 Argon2id 校验，另存 SHA-256 摘要用于查找账号。管理员不能给两个账号设置相同密钥。旧库只有不可逆的 Argon2id 值，因此迁移后的 `legacy` 账号使用有限的旧密钥回退校验；重置密钥后即使用常规摘要查找。所有浏览器草稿以 `draft:<user_id>:<draft_id>` 为键。旧版无归属草稿不自动迁移，以避免误分配。

## 分享边界

分享是不可变快照，不建立跨账号可编辑引用。分享者的后续新增内容不会自动扩大授权范围；接收者导入后拥有独立数据。链接包含 256 位随机令牌，数据库仅保存其 SHA-256 摘要。普通账号持有链接即可预览；无需另外添加好友或授予账号权限。链接仅在有效期内且分享者启用时可访问。

### 单条收藏

仅复制该收藏的原文、解释、评分、直接关联标签，以及这些标签所需的祖先节点。不会复制兄弟标签、空的无关分类或任何其他收藏。这里的标签全部为分享范围，界面应由用户选择单条分享时明确理解。

### 分类子树

以节点完整路径 `R` 为范围，使用 `path == R || strings.HasPrefix(path,R+"/")` 判断包含关系，避免 `Go` 与 `Golang`、`A/B` 与 `A/BB` 混淆。不使用 SQL LIKE 匹配树路径，因此 `%` 和 `_` 只是普通标签字符。

1. 取 `R` 和全部后代标签，包括空节点。
2. 取至少有一个标签位于范围内的收藏，含归档收藏。
3. 对这些收藏裁剪标签，只保留范围内标签。解释和原文是收藏整体，仍完整分享。
4. 剥离 `R` 的祖先前缀，仅保留其名称作为快照根。例如 `私有/技术/编程` 映射为 `编程`，`私有/技术/编程/Go` 映射为 `编程/Go`。不泄露祖先或树外的分类名称。
5. 按路径排序节点，按原收藏 ID 排序记录，序列化为 Bundle。快照上限 16 MiB。

## 层次合并

接收者选择已有标签 `D` 或根目录。对快照中的每个路径 `p` 使用确定性映射：根目录时为 `p`，否则为 `D + "/" + p`。无标签单条收藏导入到非根目录时关联到 `D`。客户端不提交自己的树或记录，服务端始终使用已保存快照。

节点身份由接收者 ID 和映射后的完整路径确定。逐级创建缺失节点、复用相同路径的本地节点并保留其 ID。**不根据叶子名称合并不同父节点，不移动本地树，也不复用分享者的节点 ID。**例如本地已有 `工作/Go` 时，导入 `阅读/Go` 仍建立独立分支。树边只能连接同一账号中短一段的父路径，因此不会产生环。

对于映射后的收藏，按当前用户内的原文摘要查找，并再次比较原文字节以检测哈希碰撞。新收藏使用快照评分；已有收藏保留接收者评分和归档状态。标签取集合并集，然后以路径段构造 trie（前缀树），删去同时存在的祖先关联，仅保留最细后代。相邻兄弟与其他树分支保持不变。该过程只简化收藏关联，不删除任何标签树节点。

说明按固定分隔符 `\n\n---\n\n` 拆为片段，以原有顺序保留本地内容，再追加尚未出现的快照片段。结果完全一致时不写入、不递增版本。重复导入到相同位置因此满足幂等性；用户明确改选位置时可以产生新的关联路径，这是不同的导入请求。

令 `L` 为所有待合并关联标签的总路径长度，`K` 为不同关联标签数。祖先消除使用集合和按路径段构建的 trie，约为 `O(L + K log K)`（包含排序），避免对标签集合做平方级两两比较。快照范围扫描是当前用户标签与收藏数据的线性遍历；逐级持久化节点需与路径深度成比例的数据库查询。当前项目维持单实例运行，写请求通过同一互斥门串行化；数据库唯一索引是额外完整性约束，不声称支持多实例并发导入。

## 预检与提交

预检在事务中执行完整映射、校验和合并，返回后回滚，因此也会检测深度映射后路径超过 1024 字节、目标不存在等错误。返回新增、合并、无需修改、标签新增与复用计数。

预检版本绑定分享 ID、快照摘要、目标路径和接收者当前数据版本。提交再次检查链接状态、分享者状态、接收者身份、目标及版本，并在同一事务中执行全部变更。不同链接、不同目标、本地收藏或标签发生变化时，旧预检失效并返回 409。其他用户的数据变化不影响该接收者的预检。撤销或过期后预检令牌不能绕过链接校验。失败不会留下半棵树或部分收藏。

## API

所有路径以 `/api/v1` 为前缀，写入仍要求 Cookie + CSRF 请求头或 Bearer 认证。

| 方法与路径 | 含义 |
| --- | --- |
| `GET /admin/users?q=...` | 管理员搜索普通用户 |
| `GET /admin/users/{id}` | 管理员读取普通用户详情 |
| `POST /admin/users` | 创建普通用户，提交 `username,api_key,disabled` |
| `PUT /admin/users/{id}` | 编辑普通用户，`api_key` 留空保留原密钥 |
| `DELETE /admin/users/{id}` | 删除普通用户及其全部服务器数据 |
| `POST /shares` | 创建快照，提交 `kind=bookmark,bookmark_id` 或 `kind=tag,tag_id`，可选 `expires_days` |
| `GET /shares` | 查看本人创建的分享元数据，不返回令牌或快照 |
| `DELETE /shares/{id}` | 撤销本人分享 |
| `GET /shares/{token}` | 普通用户凭链接预览快照 |
| `POST /shares/{token}/preview` | 提交 `target_path`，预检合并，返回 `counts,revision` |
| `POST /shares/{token}/commit` | 提交相同 `target_path` 和预检 `revision`，事务导入 |

创建响应为 `{share, path:"/share/<token>"}`，前端以自身 origin 拼接可分享网址。管理员和分享列表均无法读回链接令牌。不存在、撤销、过期或分享者不可用的链接统一返回 404；未登录返回 401；角色错误返回 403；数据或目标版本不匹配返回 409。
